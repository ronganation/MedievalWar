## 2. Standard Faction Workflow

Use this sequence for every new faction review.

### Gate A: Whole-Package Due Diligence

- [ ] Open the Realm package entry point or README.
- [ ] Inspect folder structure and current authority index.
- [ ] Read controlling historical, Registry, character, governance, regional, institutional, military, economy, route, settlement, population, AI, diplomacy, Opening State, audit, and handoff authorities as relevant.
- [ ] Identify current files by content and authority status rather than filename alone.
- [ ] Compare against developed Realms across relevant theaters.
- [ ] Record verified facts, uncertainties, owner boundaries, and implementation limits.

### Gate B: Bounded Authority-Surface Assessment

- [ ] Map existing authority coverage.
- [ ] Identify substantive gaps.
- [ ] Distinguish a genuine missing capability from a symmetry-only wrapper.
- [ ] Identify shared-framework ownership versus Realm ownership.
- [ ] Determine whether new specialist files are justified.
- [ ] Preserve Unknown, ReviewOnly, Quarantined, external-owner, and validation-pending states.
- [ ] Do not create technology content until the assessment passes.

### Gate C: Population, Recruitment, Training, Obligation, and Recovery

- [ ] Confirm population and community authority.
- [ ] Confirm finite recruitment sources and pool constraints.
- [ ] Confirm military obligation and contribution interfaces.
- [ ] Confirm training, formation, readiness, equipment, command, and facility dependencies.
- [ ] Confirm casualty, demobilization, replenishment, and recovery behavior.
- [ ] Create or strengthen a specialist authority only where the package lacks substantive coverage.

### Gate D: Knowledge, Technology, Adoption, Reform, and Realm Development

- [ ] Build from the complete immediate substantive source when a predecessor exists.
- [ ] Preserve the Realm's actual institutions, geography, economy, military, routes, communities, and historical constraints.
- [ ] Define adoption and diffusion rather than an abstract universal tech tree.
- [ ] Separate knowledge, capability, program, investment, realization, maintenance, and active output.
- [ ] Keep player choice and competing investments where useful.
- [ ] Avoid unlimited cultural combinations and forced binary forks.
- [ ] Prevent unlocks from creating resources or active state.
- [ ] State honest Static-Checked and Unreal Engine 5.8 validation boundaries.

### Gate E: Package Integration

- [ ] Update README or package entry point by copy-first additive rebuild.
- [ ] Update current-authority index or manifest if one exists and if owner-authorized.
- [ ] Place assessments in workflow, audit, or handoff folders.
- [ ] Place substantive cross-cutting authorities according to actual package ownership.
- [ ] Perform section-by-section and literal completeness checks.
- [ ] Record rollback, evidence, owner gates, and next bounded action.
- [ ] Stop before Opening State, payload, importer, runtime, or Unreal activation unless explicitly authorized.
