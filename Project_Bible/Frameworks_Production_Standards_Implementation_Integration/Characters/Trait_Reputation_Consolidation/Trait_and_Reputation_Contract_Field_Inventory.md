# 3. Runtime Ownership Review

## Authoritative runtime state

Only fields classified **Authoritative Runtime State** constitute mutable constitutional truth. Ownership remains partitioned:

- Trait Authority owns Character Trait State and Trait-bounded provenance/visibility state.
- Reputation Authority owns Character-Audience Reputation State and bounded Reputation Source References.
- Character Foundation owns the canonical represented person reference and Foundation core, not Trait or Reputation state.
- Historical Memory owns evidence, narrative, memory, reception sources, and legacy.
- Character Network or Historical Memory owns authoritative information access, depending on source.
- Migration/validation authority owns quarantine resolution state.

## Transient command and query data

Command requests, query requests, proposed changes, evaluation results, summaries, and influence contributions are **Derived Query/Result Data** unless an accepted owner transition writes authoritative runtime state. A derived result does not become constitutional truth merely because it is displayed, cached, or consumed.

## Sole-writer invariants

- Trait acquisition and transition write only through Trait Authority.
- Reputation evaluation and epithet adoption write only through Reputation Authority.
- Strategic consumers remain sole writers of their own outcomes.
- AI can read, evaluate, explain, and propose, but cannot write authority-owned state.
- Triggering an event does not transfer ownership to the triggering system.

## Non-ownership confirmation

Trait owns no identity, readiness, authority, office, title, claim, current health truth, archetype, directed relationship, memory, reputation, or fact. Reputation owns no fact, evidence, narrative, memory, title, office, claim, legitimacy, authority, or universal audience truth.

# 4. Save Ownership Review

## Saved as authoritative specialist state

Trait Authority saves only the Character Trait State elements required for continuation, validity, visibility, transition, and provenance.

Reputation Authority saves only Character-Audience Reputation State and bounded source-reference elements required for continuation, contradiction, visibility, provenance, and audience-specific evaluation.

## Not normally saved

- commands;
- transient query requests;
- influence results;
- visibility results;
- summaries;
- evaluation results that can be regenerated;
- validation results not required for trace or migration;
- derived caches without an approved cache contract.

## Saved outside Trait and Reputation

- Canonical person identity: Character Foundation.
- Evidence, narrative, memory, and legacy: Historical Memory.
- Directed knowledge/access: Character Network or applicable information owner.
- Migration mappings and quarantine: Migration Registries/migration runtime.
- Save versions: save and migration runtime.
- Reason traces: shared trace infrastructure or approved owner partition.

## Save invariants

1. Opening State data initializes new campaigns once.
2. Loading an advanced save never reapplies defaults.
3. Definition data is versioned but is not copied into every character save as mutable truth.
4. Derived results are regenerated unless an approved deterministic cache exists.
5. Source references do not duplicate source-owned substantive state.
6. Deprecated identifiers and legacy generic containers are not emitted after validated conversion.
7. Save-load-save preserves audience differences, visibility, provenance, references, and deterministic continuation.

# 5. Migration Ownership Review

Migration Registries and migration runtime own:

- source identifier resolution;
- direct source-to-canonical mapping;
- migration versions;
- ambiguity classification;
- quarantine;
- mapping provenance;
- migration completion state.

Trait and Reputation owners receive accepted destination state only after migration validation. Migration cannot reclassify the passed audit, invent an ID, create a registry, infer an audience, fabricate evidence, or use a display label as identity.

## Required migration separation

- Trait migration records preserve locked audit classification and action.
- Reputation migration records require subject, audience evidence, source evidence, and opening-date validity.
- Canonical character references resolve through Migration Registries.
- Historical Memory source truth remains external to Reputation migration records.
- Unsupported legacy modifiers remain migration evidence rather than direct strategic effects.
- Ambiguous records enter Quarantine Records with dependencies and provenance.
- Conversion remains versioned, deterministic, direct, and idempotent.

# 6. Validation Review

## Fatal

- A required contract field is omitted such that ownership, writer, source, save, migration, or determinism cannot be validated.
- An authoritative runtime element has more than one writer.
- A derived result is treated as constitutional truth without an accepted state transition.
- Trait stores or creates identity, readiness, authority, office, title, claim, health truth, archetype, relationship, memory, reputation, or fact.
- Reputation stores or creates fact, evidence, narrative, memory, title, office, claim, legitimacy, authority, or universal audience truth.
- Historical Memory source truth is copied into Reputation as duplicate authority.
- Opening State data overwrites advanced save state.
- Static definition data contains current holder, current acceptance, or another mutable outcome.
- A hidden state leaks through a visibility, summary, influence, reason, or validation result.
- Migration invents an ID, audience, source, registry, Gameplay Tag, or ownership decision.
- Display labels, filenames, indexes, load order, or object addresses become primary identity.
- Unknown or ambiguous data is guessed rather than quarantined.
- Alias chains or deprecated outputs are accepted.
- Equal state, inputs, versions, and seed produce unequal state, events, traces, or diagnostics.

## Warning

- A field duplicates data owned by another contract or subsystem.
- A definition field has no runtime consumer or validation purpose.
- An optional strength field becomes a universal score.
- A derived result is persisted without cache ownership and invalidation.
- A source reference lacks source version or validity state.
- A command lacks provenance, effective ordering, validation outcome, or reasons.
- A Reputation state lacks a bounded audience.
- A Trait influence channel implies direct strategic mutation.
- A summary collapses conflicting audiences into universal truth.
- A validation or trace field exposes unauthorized hidden information.

## Completeness rule

Every later exact implementation field must map to exactly one row in this inventory or enter quarantine/review. Multiple exact fields may implement one semantic row. One exact field may not silently combine several constitutional meanings without an explicit Refactor disposition and decomposition rule.
