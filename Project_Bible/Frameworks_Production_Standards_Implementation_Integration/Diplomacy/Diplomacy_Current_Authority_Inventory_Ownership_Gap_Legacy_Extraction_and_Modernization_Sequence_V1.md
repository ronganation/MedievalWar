## 1. Executive Verdict

A shared Diplomacy, Treaty, War, Peace, and Political Settlement owner is required.

The requirement is not inferred from a desire for symmetry. The current shared integration authority `Economic_Geography_Settlement_Value_and_Diplomatic_Exchange_V1.md` explicitly identifies a missing general Diplomacy, Treaty, and War-and-Peace constitutional owner. Current realm authorities have already developed substantial, compatible diplomatic architecture, but they distribute ownership differently and remain bounded to their respective realms.

The correct modernization path is:

```text
Verify current and legacy sources
then
Preserve all compatible substantive portfolios
then
Create one complete shared diplomacy foundation
then
Independently compare the foundation against every accepted source family
then
Modernize vassalage and subordination as a justified specialist framework
then
Apply a remaining-specialist coverage and stop gate
then
Validate developed-realm conformance without forcing symmetry
```

The first shared foundation must be additive and implementation-helpful. It must not become a short integration summary. It must preserve the strongest compatible content already present across Ireland, Wales, Flanders, Valencia, Zaragoza, Almoravid, Seville, Badajoz, Normandy-facing military diplomacy, economic exchange, delegated authority, dynasty relationships, Papal relations, law, military decision inputs, and legacy systems.

## 2. Purpose

This audit controls the modernization of Medieval War diplomacy. It:

- records the accepted current and legacy source set;
- distinguishes shared constitutional mechanics from realm content;
- identifies explicit ownership gaps;
- preserves substantive legacy ideas without preserving obsolete assumptions as current canon;
- establishes the required carry-forward portfolio for the shared foundation;
- defines specialist-owner boundaries;
- prevents realm-specific opening facts from becoming universal system facts;
- establishes a phased production sequence with dependencies, acceptance criteria, evidence, rollback, and owner gates;
- prevents shallow successors, uncontrolled file multiplication, premature Registry work, premature Opening State work, and premature Unreal activation.

This audit creates no diplomatic relationship, contact, envoy, message, proposal, treaty, agreement, obligation, war, peace, tribute, passage, hostage, clientage, vassalage, coalition, settlement, runtime object, Registry row, Opening State record, importer payload, or Unreal asset.

## 3. Governing Method

### 3.1 Copy-first additive authority rule

Every successor governed by this audit must:

1. identify its complete immediate substantive source set;
2. preserve all compatible substantive content;
3. record source fingerprints where physically available;
4. expand weak or compressed portfolios rather than deleting them;
5. modernize outdated assumptions in place;
6. preserve ownership boundaries and owner-routed execution;
7. retain player-facing content, AI content, validation content, save content, migration content, and rollback content;
8. record every substantive removal in a removal or disposition ledger;
9. compare source coverage against successor coverage section by section;
10. state validation status honestly.

### 3.2 Current-before-legacy rule

Use this precedence:

```text
Bryan's explicit current instruction
then
Project Bible 2.4
then
Design Expansion Checklist 3.7
then
current shared constitutional and integration authorities
then
current developed-realm diplomacy authorities
then
current specialist realm authorities and cross-realm interfaces
then
legacy system sources as extraction authorities
then
comparative game and mod references as ideas only
```

Legacy sources are not discarded. They are preserved as design-intent and portfolio sources, but current constitutional ownership, material conservation, personhood, uncertainty, temporal, save, migration, and no-mutation rules control their modernization.

### 3.3 No symmetry-only output

A new file is justified only when it:

- owns a distinct lifecycle or portfolio;
- avoids duplicating an existing owner;
- materially reduces ambiguity or implementation risk;
- adds reusable capability across realms;
- cannot be safely contained in an existing accepted authority.

A matching filename in another realm is not sufficient justification.

## 11. AI Constitution

### 11.1 AI may

- identify a problem or opportunity;
- request information;
- evaluate confidence and staleness;
- identify valid principals and representatives;
- compare proposals and counteroffers;
- request feasibility from material owners;
- evaluate cost, risk, duration, reversibility, dependence, sovereignty, and domestic sustainability;
- identify narrower alternatives;
- recommend mediation, delay, abstention, or no action;
- explain decisive blockers and unknowns;
- submit owner-routed commands.

### 11.2 AI may not

- read hidden external state;
- infer reverse-directed relationships;
- use later historical knowledge;
- invent a counterparty or representative;
- invent consent;
- ratify for another owner;
- create money, property, goods, people, forces, horses, ships, officers, routes, access, transport, supply, titles, claims, institutions, or agreements;
- declare war, move forces, make payment, release a person, transfer property, or execute settlement without the responsible owner;
- convert pressure into command;
- convert relationship into agreement;
- convert alliance into military contribution;
- force action when abstention is preferable.

The player should normally see:

- the relevant diplomatic principal and counterparty;
- current contact and recognition;
- known relationship and agreement state;
- active war, ceasefire, truce, peace, passage, tribute, guarantee, hostage, clientage, or coalition state where known;
- proposed and requested terms;
- representative authority and ratification requirements;
- promises versus confirmed capacity;
- deadlines, duration, review, withdrawal, and expiry;
- decisive constraints;
- material-owner dependencies;
