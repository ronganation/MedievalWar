## 2. Purpose

The Framework Architecture Map defines how Medieval War's constitutional framework families work together, which owner controls each reusable concept, which integration authorities connect owners, which predecessors remain provenance, which older authorities are superseded, and when new framework work is justified.

The project is beyond unrestricted framework creation. Character, Dynasty, Campaign, Realm, World, Historical, Political Constitution, and Diplomacy families now possess current static-design authority spines or bounded integration closures. The default need is governance, current routing, owner-gated implementation discovery, evidence, and anti-churn discipline.

This map answers:

- Which framework owns each reusable concept?
- Which other authorities may reference or consume it?
- Which files are current substantive authorities?
- Which records are integration contracts rather than state owners?
- Which predecessors remain required provenance?
- Which workstreams are closed for current static design?
- Which exact evidence can reopen a closed family?
- How do definitions, Opening State, runtime, evaluation, presentation, saves, migration, and evidence remain separate?
- When is a new framework, addendum, direct-reference migration, structural remedy, or no-action disposition justified?

## 3. Core Architecture Thesis

```text
One Recurring Ownership Problem
Should Have
One Constitutional Owner
```

Other frameworks and integration authorities may:

- reference the owner;
- consume owner-provided outputs;
- contribute typed domain context;
- request owner feasibility or transactions;
- define validation at their boundary;
- retain holder-specific knowledge and explanation references where authorized.

Other frameworks and integration authorities may not:

- duplicate authoritative mutable state;
- redefine the same universal structure;
- create a competing subsystem;
- convert observations or interpretation into owner truth;
- store mutable outcomes in definitions;
- author external private state locally;
- treat silence as consent;
- overwrite Opening State or advanced Campaign state;
- broaden implementation evidence beyond its exact scope.

## 4. Medieval War Identity Gate

Every framework remains subordinate to this identity:

```text
Medieval II Campaign Spine
+ Selective Character And Political Causality
+ Strategic Institutions And Regional Difference
+ Finite Material And Human Capacity
+ Limited Routine Player Workload
+ Historical Pressure Without Scripted Outcomes
+ Owner-Routed Deterministic Implementation
```

A framework fails the architecture gate if it:

- pulls attention away from map, armies, settlements, diplomacy, succession, institutions, population, economy, logistics, or territory without proportional value;
- creates routine clicks rather than meaningful strategic choices;
- duplicates current owner state;
- treats people as modifier bundles or inexhaustible pools;
- treats children as small adults;
- treats Dynasties as one ruler;
- treats Relationships as automatic loyalty or one mutual score;
- treats Claims as ownership;
- treats recognition or legitimacy as capacity;
- treats narrative or memory as fact;
- treats a strong ruler as a strong transition;
- derives Campaign Season or Historical progression from Biological months;
- uses a date to force an outcome or Character spawn;
- allows AI or integration evaluators to mutate unrelated owner state;
- creates nondeterministic results from equivalent authoritative inputs.

### Layer 7F: Economic and Material Flow Family

Owns shared economic and material-flow definitions and interfaces for resources, production, stock, market, trade, treasury, fiscal state, credit, shipment, delivery, and conservation. The shared Economic and Material Flow authority family and the developed-Realm conformance pass are complete for the accepted current five-Theater static-authority baseline under the 2026-09-21 Design Expansion Checklist 3.7 closure update. No next existing-Realm Economy audit remains. Future Realms and factions complete the Economic and Material Flow intake gate during initial development. Completed Realms reopen only for a material evidence-backed trigger, changed controlling contract, demonstrated implementation defect, genuinely new reciprocal interface, or owner adjudication. Static-authority closure does not claim runtime implementation, active economic state, Opening State bindings, payload generation, importer execution, Unreal mutation, or implementation validation.

### Layer 8: AI and Decision Integration

AI consumes actor-visible owner state, evaluates, abstains, explains, and proposes. Owners validate and execute.

### Layer 9: Content Authorities

Realm, Faction, Character, Dynasty, institution, Theater, Personality, AI, and Opening State files provide historically grounded content. Content may specialize frameworks but cannot redefine universal ownership.

## 21. Framework Creation Gate

A new shared framework may be created only when all are true:

- the issue recurs across multiple Realms, Theaters, Dynasties, or major systems;
- no current owner can represent it cleanly;
- the capability produces meaningful strategic consequences;
- content, a typed record, a processor, a DataTable, an integration contract, or a bounded extension is insufficient;
- player workload remains concise;
- AI can interpret and explain it through owner state;
- definition, Opening State, runtime, presentation, persistence, and evidence can be separated;
- determinism, saves, migration, replay, rollback, and performance can be addressed;
- no duplicate mutable owner is created;
- dependencies, acceptance criteria, evidence, rollback, and owner gates are explicit.

If any condition fails, prefer content authoring, a typed record, an integration contract, a focused revision, an addendum, direct-reference migration, deferral, quarantine, no action, or rejection.
