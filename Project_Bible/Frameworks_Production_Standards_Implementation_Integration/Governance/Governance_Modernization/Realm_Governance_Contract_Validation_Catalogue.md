# 1. Concise Verdict

All **180 approved Realm Governance semantic fields** now have exactly one primary, engine-agnostic validation entry. The catalogue validates ownership, canonical references, save integrity, migration safety, dependency order, observer safety, cross-authority boundaries, supersession, and deterministic processing across all six approved contracts.

The catalogue adds no contracts or fields. It creates no runtime code, runtime type, save schema, identifier, registry, Gameplay Tag, Unreal symbol, or content. Validators accept, reject, diagnose, invalidate derived results, trace, or quarantine. Validators never become state writers.

`Crown Authority`, `Regional Authority`, ruler-owned `Domain Capacity`, and automatic loyalty remain superseded. Governance Performance Result remains derived and cannot become authoritative state or a mutation channel.

## Severity Meaning

- **Critical:** Reject the affected definition, initialization, mutation, save/load, migration, quarantine resolution, or result consumption because constitutional ownership, authoritative-state integrity, or deterministic safety would otherwise fail.
- **Error:** Reject an invalid field value, reference, or state transition while preserving the last valid authoritative state.
- **Warning:** Preserve valid state but report quality, usefulness, readiness, workload, uncertainty, or explainability risk. A Warning never permits guessing or ownership transfer.
- **Informational:** Record provenance, compatibility, reason, ordering, or audit information without mutating state or blocking an otherwise valid operation.

# 4. Ownership Validation Review

## Sole-writer enforcement

- Realm Governance definition-authoring/import is the only writer of Governance Structure Definition content.
- Realm Governance runtime authority is the only writer of Governance Administration, Reach, Capacity, and Performance state.
- Realm Governance evaluation produces Performance Results, but the result remains read-only.
- External authorities may provide references, bounded query results, or source events. External authorities do not write Governance state directly.
- Governance results may inform external commands. The receiving constitutional owner validates and writes its own state.

|---|---|---|

No validation entry authorizes Realm Governance to own or mutate law, policy, authority, delegation, regency, relationships, information access, memory, narrative, Reputation, Traits, titles, claims, succession, dynasties, economy, military, province, or public-order truth.

## Definition content

Governance Structure Definition must remain versioned definition content. Validation rejects mutable holders, current arrangements, current reach, current capacity, performance outcomes, relationships, or external-domain outcomes in definition content.

## Mutable Governance state

Save validation covers:

- Governance Administration State
- Governance Reach State
- Governance Capacity State
- Governance Performance State

## Derived results

Governance Performance Result is not authoritative saved state. Validation must invalidate and recompute derived results when a source state, source version, observer scope, or information scope changes. No derived result may survive load as mutable Governance truth.

## Save integrity rules

1. Validate compatible content, contract, save, migration, and mapping versions before loading mutable Governance state.
2. Preserve static definition, mutable state, and derived result separation.
3. Resolve canonical Realm and external-owner references before accepting dependent Governance state.
4. Reject missing or corrupted required Governance state.
5. Fail safely or quarantine unresolved imported/migrated references.
6. Apply Opening State initialization only to new campaigns.
7. Preserve advanced-save precedence over all Opening State defaults.
8. Preserve vacancies without deleting administrative structures.
9. Prevent dead or inactive persons from retaining living administrative agency.
10. Prevent Reach from loading as jurisdiction or control.
11. Prevent Capacity from loading as readiness, authority, or Domain Capacity.
12. Prevent Performance from loading as legitimacy, authority, Crown Authority, or Regional Authority.
13. Preserve deterministic continuation, source references, and compatible versions.
14. Reject partial state mutation after a failed load.
