# 1. Concise Verdict

The authoritative Historical Memory Contract Field Inventory contains **270 semantic field rules** across all 16 approved contracts. This catalogue converts every field rule into exactly one formal, engine-agnostic validation entry.

The result provides complete Static-Checked validation coverage for definitions, Opening State initialization, runtime records, queries, saves, migration, quarantine, provenance, audiences, witness/testimony boundaries, fact separation, Network/Character Foundation references, Reputation integration, and deterministic processing.

The catalogue defines validation responsibilities only. It does not create executable validators, implementation symbols, IDs, registries, Gameplay Tags, or content.

## Severity Meaning

- **Fatal:** Reject the affected definition, initialization, command, record write, query consumption, save/load, migration step, or quarantine resolution. Never write invalid authoritative state.
- **Warning:** Preserve valid authoritative state, report the issue, and suppress unsafe derived output where appropriate. A warning never authorizes guessing or ownership transfer.
- **Informational:** Record trace, completeness, provenance, or ordering information without blocking an otherwise valid operation or changing authoritative state.

# 3. Validator Ownership Review

## Validation is not mutation authority

A validator may:

- inspect authorized inputs;
- accept or reject a definition, initialization, command, result, record write, save/load, migration step, or quarantine resolution;
- produce Fatal, Warning, or Informational diagnostics;
- emit deterministic reason traces;
- request or preserve quarantine;
- block unsafe persistence or consumption.

A validator may not:

- write accepted Historical Memory state;
- alter deterministic facts or participation;
- create person identity or living agency;
- create Network relationships or knowledge;
- create current character Reputation;
- create titles, offices, claims, laws, legitimacy, jurisdiction, or authority;
- invent facts, evidence, audiences, witnesses, narratives, memories, IDs, registries, Gameplay Tags, or implementation symbols;
- reassign or reopen ownership.

## Validator responsibilities

### Historical Memory Fact Reference Validator

Validates that Historical Memory references a real external fact, preserves chronology and subject compatibility, and never becomes fact owner.

### Historical Memory Evidence Validator

Validates Evidence Definition and Evidence Runtime State, including source, subject, chronology, creator/custodian/witness references, quality dimensions, accessibility, contradiction, preservation, visibility, and provenance.

### Historical Memory Witness and Testimony Validator

Validates person identity, life state, fact/event presence or access, recording chronology, testimony survival, bounded credibility context, and the prohibition on new testimony from dead witnesses.

### Historical Memory Narrative Validator

Validates Narrative Definition and Narrative Runtime State, including evidence basis, assertions/fact separation, authorship, sponsorship, audience, accuracy, partisanship, contradiction, rivals, lifecycle, suppression, preservation, and provenance.

### Historical Memory Reception and Tradition Validator

Validates bounded audiences, awareness, acceptance/rejection, institutional adoption references, political use, persistence, memory basis, contradiction, suppression, decay, revival, and separation from current character Reputation.

### Historical Memory Record Validator

Validates historical records as information objects and prevents records from directly creating legal validity, claims, titles, offices, property, jurisdiction, legitimacy, or authority.

### Historical Memory Commemoration Validator

Validates sponsor, subject, audience, prerequisites, external institution/location references, lifecycle, preservation effect, and the prohibition on automatic reception or authority.

### Historical Memory Preservation Validator

Validates preservation of historical information while keeping physical buildings, institutions, offices, logistics, settlements, and save infrastructure externally owned.

### Historical Memory Legacy Validator

Validates valid death/inactivity basis, historical support, audiences, preservation, contradiction, and the prohibition on living agency, new testimony, current Reputation ownership, or later-history preload.

### Historical Memory Provenance Validator

Validates bounded source links, source owner, source record, chronology, version, validity, migration provenance, and the prohibition on copying source truth.

### Historical Memory Query Boundary Validator

Validates observer/audience information, bounded channels, source-state versions, uncertainty, influence limits, and the consuming owner's sole-write authority.

### Historical Memory Migration and Quarantine Validator

Validates extraction, semantic classification, direct mapping, chronology, witness, audience, destination, dependencies, quarantine, idempotence, and migration completion without invention or guessing.

# 4. Migration Validation Review

## Migration validations must confirm

1. Exact source document, schema, record, field, key, or save location is preserved.
2. Raw source value remains available where policy permits.
3. Normalization never replaces raw evidence.
4. Source semantics are separated into fact, participation, testimony, evidence, narrative, reception, memory, Reputation source, historical record, commemoration, preservation, legacy, archive, or quarantine.
5. Canonical subjects resolve through Migration Registries.
6. Audiences and witnesses are supported by source evidence and are never invented.
7. Chronology and opening-date eligibility are valid.
8. Destination contract is approved and ownership-preserving.
9. Unknown or conflated meanings enter quarantine.
10. Mapping versions and dependencies are recorded.
11. Direct mappings are used; alias chains are prohibited.
12. Deprecated identifiers are never written to modern state.
13. Migration is idempotent and deterministic.
14. Migration completion is recorded only after all Fatal validations pass.
15. Opening State defaults never overwrite advanced save state.

## Mandatory quarantine cases

- unknown or ambiguous identity;
- missing or conflicting fact reference;
- unsupported participation or witness presence;
- missing audience evidence;
- conflated memory and Reputation meaning;
- unmatched field or destination;
- chronology conflict;
- corrupt source data;
- unsupported save or migration version;
- unresolved dependency;
- duplicate or colliding legacy labels where semantics cannot be proven.

Quarantine preserves source values, provenance, dependencies, reason, versions, resolution status, evidence, authority, and outcome. Quarantine never repairs data by guessing.

# 5. Save Validation Review

## Before save write

Validate:

- owner partition boundaries;
- canonical external references;
- Fact Reference validity;
- evidence, testimony, narrative, reception, tradition, record, commemoration, preservation, and legacy state;
- source provenance;
- version compatibility;
- absence of deprecated identifiers;
- absence of duplicated Character Foundation, Character Network, current Reputation, institution, title, claim, law, or authority truth;
- deterministic continuation state.

## Before save load

Validate:

- save schema and content versions;
- migration path and completion markers;
- canonical reference resolution;
- dependency order;
- quarantine dependencies;
- Opening State suppression for advanced saves;
- historical uncertainty preservation;
- witness life-state compatibility;
- audience-specific reception;
- external source versions.

## Save failure behavior

Fatal save validation rejects the unsafe partition or load/conversion step and preserves the last valid state or source save. Partial mutation must not be committed. Warning and Informational diagnostics never authorize repair by assumption.

## Save invariants

- Definitions remain immutable content, not mutable save state.
- Opening States initialize new campaigns once.
- Historical Memory saves only owner-specific state and references.
- Derived queries regenerate unless an approved deterministic cache exists.
- External owners save external truth.
- Save-load-save preserves state required for equal subsequent evaluation.

# 6. Determinism Review

Validation must follow this dependency order:

1. Definition and content versions.
2. Save and migration versions.
3. Canonical identities and external references.
4. Fact References and chronology.
5. Evidence and Historical Records.
6. Witness/Testimony References.
7. Narratives.
8. Memory Reception and Memory Traditions.
9. Commemorations and Preservation.
10. Legacy.
11. Provenance.
12. Queries and influence results.
13. Migration completion and quarantine dependency resolution.
14. Save partition acceptance.
15. Trace emission.

Within each phase:

- sort by stable contract order;
- sort by stable record/reference when available;
- sort people and institutions by canonical reference;
- sort audiences before reception evaluation;
- sort evidence sets, source sets, contradiction sets, rival narratives, custody chains, copies/translations, and dependency references deterministically;
- apply fixed field-rule order;
- apply versioned thresholds and stable numeric rounding;
- use seeded randomness only where explicitly authorized;
- record tie-break reasons;
- never depend on wall-clock time, frame timing, memory address, unordered-container iteration, asset discovery order, load order, or UI order.

Equal state, inputs, content version, contract version, save version, migration version, mapping version, and seed must produce equal diagnostics, accept/reject outcomes, quarantine decisions, traces, and accepted authoritative state.

# 7. Risks

| Risk | Consequence | Control |
|---|---|---|
| Validator becomes another writer | Duplicate ownership | Validators accept/reject only; owner writes state |
| Validation name treated as an ID | Unapproved registry creation | Validation names remain descriptive labels |
| Informational issue used as authority | Nonbinding trace treated as truth | Informational output never mutates or authorizes |
| Warning used to bypass fatal boundary | Invalid state persists | Identity, fact, source, audience, witness, save, and migration integrity remain Fatal |
| Fact validation occurs after narrative | Narrative can influence fact acceptance | Validate fact references first |
| Witness validation omits life state | Dead witness creates testimony | Foundation life-state check required |
| Reception validation omits audience | Universal memory state emerges | Audience mandatory |
| Reputation copied into memory | Duplicate audience truth | Validate current Reputation boundary |
