## 4. Question-by-Question Gate Result

### 4.1 Safe Pool Versus Emergency Overdraw

```yaml
safe_pool_concept_in_current_pool_authority: NotExplicitlyIntegrated
emergency_overdraw_concept_in_current_pool_authority: NotExplicitlyIntegrated
source_available_in_peasantry_framework: true
successor_action: AddTypedInterfaceWithoutInventingExactThresholds
```

The peasantry specialist distinguishes safe military allocation from emergency overdraw and supplies pressure based on overdraw depth, service distance, duration, losses, source condition, and repeated muster. The pool constitution should consume that interface without taking population-owner or economy-owner calculations.

### 4.2 Demobilization and Return

```yaml
demobilization_mentioned: true
demobilization_full_contract_in_pool_authority: incomplete
assignment_owner_has_DemobilizationAndReturn_reservation: true
successor_action: AddPoolSideReleaseAndRecoveryReceiptContractByReference
```

The existing pool authority permits formations to demobilize and prohibits generic-pool conversion, but does not define a complete pool-side demobilization state and receipt contract. The assignment constitution owns the transaction and reservation lifecycle. The pool successor should define what receipt changes pool availability without duplicating assignment execution.
