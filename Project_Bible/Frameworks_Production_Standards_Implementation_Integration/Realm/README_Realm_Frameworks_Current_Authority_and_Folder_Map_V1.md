## 1. Purpose

This README is the local navigation and authority-selection surface for the shared Realm framework family.

It identifies the role, precedence, and boundaries of the files physically owned by this folder. It does not replace their substantive content, promote any candidate, authorize Realm-package rewrites, or activate scenario, Registry, runtime, save, importer, payload, or Unreal state.

## 2. Folder Ownership

This folder owns the reusable Realm-family methodology, strategic-identity interpretation, package-development coverage workflow, and retained modernization audit evidence.

This folder does not own:

- Realm-specific historical truth or content packages;
- Governance, Law, office, title, claim, succession, or regency authorities owned by Governance and political-constitution families;
- Character, Dynasty, household, relationship, development, or AI state owned by their specialist families;
- universal World contracts such as Strategic Geography, Province, Supply, and Population;
- Historical Evidence, Memory, Momentum, or Emergence;
- Military and Battles framework authorities;
- Realm-specific Opening State, Registry, migration, importer, payload, runtime, save, or Unreal implementation.

Files remain with their constitutional owner even when Realm packages consume their outputs. A filename containing `Realm` does not by itself justify relocation into this folder.

## 3. Authority Precedence and Selection

```text
Project Bible 2.4
!= Design Expansion Checklist 3.7
!= shared Realm-development methodology
!= Realm Personality authority
!= package-coverage and production-flow standard
```

Use the file whose owned scope matches the task:

1. Use the Realm Development framework for shared methodology, modernization, completion, delta-audit, validation, freeze, and owner-gated implementation handoff.
2. Use the Realm Personality framework for shared Realm identity, interpretation, strategic preference, contradiction, posture, explanation, and Realm-AI input semantics.
3. Use the Realm/Faction Development Flow for `00–18` package coverage, maturity states, development stages, evidence requirements, milestones, and handoff gates.
4. Use the Realm Frameworks audit for historical source fingerprints, supersession decisions, ownership-gap evidence, and the record of how the current family was produced. The audit does not direct current methodology.
5. Use each live Realm package's README, current-authority index, and specialist authorities for Realm-specific content and current local status.

Current candidate status does not equal owner adoption. Static-document validation does not equal compile, runtime, save/load, migration, replay, performance, battle, or Unreal validation.

## 6. Coverage Families and Physical Layout

The `00–18` Realm/Faction map controls coverage, ownership, gaps, maturity, and handoff. It does not impose one universal physical folder tree.

A Realm package may use numbered folders, compact thematic folders, Realm-owned content branches, or another verified layout when the package README or authority index maps applicable coverage families to their physical owners without ambiguity.

```text
Coverage Family != Mandatory Folder
Folder Presence != Authored Definition
Authored Definition != Opening State
Opening State != Runtime Instance
Static Design Closure != Implementation Validation
```

Do not move Governance, Character, Dynasty, World, Historical, Military, or implementation-owned files into this folder merely to centralize Realm-related names.

## 7. Maturity and Temporal Boundaries

Track document, scenario, implementation, and runtime maturity separately.

The shared temporal constitution is:

```yaml
temporal_constitution:
  historical_progression: 21 months per strategic turn
  biological_progression: 7 months per strategic turn
  campaign_season_progression: 1 ordered Winter, Spring, Summer, Autumn step per strategic turn
```

The preserved older phrase describing one universal seven-month prototype turn is historical provenance only. Biological progression does not control Historical Date or Campaign Season.

## 8. Cross-Family Routing

Route work by ownership:

- Governance and political constitution own Government, Law, offices, titles, claims, succession, regency, delegated authority, legitimacy, and political transformation.
- Character and Dynasty families own people, households, directed relationships, development, succession candidates, and Dynasty strategy.
- World owns universal Strategic Geography, Province, Supply, Population, and related world-capability contracts.
- Historical owns evidence, fact claims, uncertainty, Memory, Momentum, and Emergence.
- Military and Battles owns shared military authorities, recruitment, operational frameworks, and battle consequences.
- Theater owns cross-Realm Theater context within its scope, not Realm political allegiance or Government.
- Realm packages own Realm-specific authored participation in these shared systems.
- Opening State owns scenario initialization; runtime owners execute mutable campaign state.

Related to Realm does not mean owned by the Realm framework family.
