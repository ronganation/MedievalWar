## 1. Purpose

Close Harald Hardrada as the first Phase 7 character visual fixture and return the workstream to the bounded character sequence without beginning Unreal implementation or creating another portrait prematurely.

This gate prevents four failure modes:

- extending Harald merely because the portrait workflow exists;
- choosing the next character without comparing gameplay and framework value;
- treating Harald's unusually deep first-character package as mandatory for every later character;
- beginning image generation before the selected character's authority and classification are verified.

## 3. Lessons Retained for the Phase 7 Sequence

### 3.1 Reusable lessons

- Establish one controlling identity before generating role derivatives.
- Separate facial identity authority from role-specific clothing and equipment.
- Keep character commander cards separate from bodyguard or retinue unit cards.
- Treat faction leadership as a dynamic office state rather than a unique permanent face category.
- Test accepted static images at 256, 128, and 64 pixels when compact cards are intended.
- Check grayscale, mild desaturation, frame compatibility, and wide-layout behavior when those surfaces are justified.
- Preserve source masters separately from UI derivatives.
- Archive rejected candidates and correction evidence.
- Stop image generation when the justified surface set is complete.

### 3.2 Harald-specific depth that is not automatically reusable

- Three accepted static role surfaces.
- Multiple candidates and correction passes for each surface.
- A complete first-character prototype package.
- Extensive test subfolders for all three surfaces.

Later characters may require only one identity master, or one identity master plus one role derivative. Character importance, gameplay exposure, office, battlefield or government function, historical evidence, and first-playable-slice use control the required depth.

## 5. Candidate Eligibility Gate

A candidate may enter the comparison only when all required eligibility conditions are supported by controlling records.

```yaml
required_eligibility:
  - CharacterAuthorityExistsOrCanBeVerifiedWithoutFabrication
  - OpeningStateOrHistoricalEmergenceClassificationIsKnown
  - FirstPlayableSliceOrAuthorizedEmergenceRelevanceIsMaterial
  - OwningRealmAndCanonicalFolderAreClear
  - GameplayRoleIsDistinctEnoughToTeachTheFrameworkSomethingNew
  - CharacterAuthorityCompletenessIsSufficientForVisualWork
  - NoContradictoryActiveAuthorityBlocksSelection
```

Underage characters may qualify as Opening State characters when already born. Their fixture must preserve age-appropriate political and dynastic presentation and must not fabricate an adult battlefield role.

Historical Emergence characters may qualify only when the second fixture is explicitly intended to test emergence. A date window, world-state threshold, and responsible authority must exist before image work begins.

## 6. Candidate Comparison Criteria

Compare no more than five verified characters. Use High, Medium, or Low with source-supported explanations rather than invented numerical scores.

| Criterion | Required question |
|---|---|
| Playable-slice relevance | Will the character appear materially in the first playable slice or an explicitly authorized emergence test? |
| Character-authority maturity | Are identity, chronology, role, ownership, and classification sufficiently controlled? |
| Framework-learning value | Does the character test something Harald did not? |
| UI exposure | Will the character appear often enough to justify a fixture now? |
| Battlefield or government distinction | Does the character require a meaningfully different presentation pattern? |
| Dynastic or political value | Does the character test household, succession, regency, marriage, diplomacy, patronage, or institutional influence? |
| Historical-evidence boundary | Can the visual direction be bounded honestly without claiming an authenticated likeness? |
| Scope control | Can the fixture stop cleanly without opening a new realm-wide rebuild? |
| Asset-depth economy | Can the character prove that later fixtures may use fewer surfaces than Harald? |

## 7. Recommended Second-Fixture Archetypes

The comparison should prioritize a materially different archetype rather than another ruler with the same three-surface needs.

1. **Dynastic or political woman**  
   Tests household, dynasty, patronage, diplomacy, political influence, and institutional presentation without defaulting to a battlefield-general role.

2. **Heir or underage Opening State character**  
   Tests age-appropriate identity, succession visibility, household ownership, and future progression without creating an adult command role.

3. **Non-royal battlefield or government character**  
   Tests whether a major supporting figure can use a smaller and more operational package than the faction leader.

4. **Agent or ecclesiastical character**  
   Tests priest, bishop, diplomat, spy, or specialized-agent presentation and separation from government and battlefield characters.

5. **Admiral or maritime specialist**  
   Tests naval command identity without repeating Harald's kingship, court, and council package.

The next fixture should not repeat Harald's exact ruler, campaign, and council trio unless the selected character genuinely requires all three.
