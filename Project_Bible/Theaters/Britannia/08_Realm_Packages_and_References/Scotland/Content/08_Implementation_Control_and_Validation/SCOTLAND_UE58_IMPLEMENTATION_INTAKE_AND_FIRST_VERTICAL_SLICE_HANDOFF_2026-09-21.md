## 1. Selection Verdict

Scotland is selected as the next fresh Realm implementation lane after the accepted Wales UE 5.8 read-only preview closeout.

Reason for selection:

- Norway's OS-VIS-01 through OS-VIS-05 candidate-only visible-preview sequence is already complete within its demonstrated read-only scope; its next gate is OS-REAL-01 readiness, which is blocked pending separate authorization and production prerequisites.
- Ireland is frozen against broad redesign and its implementation lane is ownership routing, importer disposition, migration, compile, runtime, save, and determinism validation rather than another Realm-design pass.
- England has a valuable military implementation path, but its phased handoff begins with separate read-only project-native architecture discovery and a three-spear calibration set.
- Scotland has a broad current design package, an exact 1 January 1062 Opening State authority, Realm AI and Personality, Registry and migration design, Character Network, military capability, settlements, routes, economy, Supply, and diplomacy, while compile, runtime, importer, save/load, migration, replay, and performance validation remain open.

This selection does not claim that Scotland is implementation-ready without intake. It selects Scotland for a bounded implementation intake followed by the smallest safe read-only candidate preview, reusing the shared Wales/Norway preview lane without cloning Realm-specific content.

## 4. Phase SCOT-IMP-00: Copy-first Read-only Intake

```yaml
phase_id: SCOT-IMP-00
purpose: Establish the exact current Scotland authority and active Unreal input surface before implementation.
mutation_authority: none
```

### Required work

1. Inventory the current Scotland package recursively.
2. Fingerprint every proposed controlling source.
3. Distinguish current authorities, immediate sources, preserved versions, reviews, manifests, static checks, and handoff artifacts.
4. Resolve filename and path ambiguity without moving files.
5. Confirm the current Scotland scenario, Realm, provider, and Registry candidate identifiers.
6. Inspect the active Unreal project for reusable provider, parser, presentation, test, and shared-tab seams.
7. Record every missing owner, missing active API, incompatible field, unresolved identifier, and intentionally empty surface.

### Acceptance criteria

- Every proposed candidate field has one named source or an explicit Unknown, IntentionalEmpty, ExternalLock, Quarantine, or NotExposed disposition.
- No preserved or superseded Scotland file is treated as current authority by recency alone.
- Ingibjorg Finnsdottir remains Scotland-owned and is not duplicated under Norway.
- The quarantined Gille project node remains quarantined and no replacement person is fabricated.
- Historical, Biological, and Campaign Season tracks remain separate.
- No exact force, route, site, property, economy, Supply, diplomatic, Network-dimension, or battle state is invented to fill an array.
- No source or Unreal file is modified.

### Evidence

- complete input manifest;
- file paths, byte counts, and SHA-256 values;
- read ledger;
- current-authority disposition matrix;
- Unreal architecture map;
- owner-routing matrix;
- unresolved and quarantine register;
- recommended smallest safe implementation seam.

### Stop gates

Stop before implementation if:

- one current authority cannot be distinguished from a competing source;
- a required candidate ID lacks an owner-controlled disposition;
- the shared provider seam would require a new parallel subsystem;
- implementation would require Registry mutation, Opening State activation, save writing, migration execution, real payload application, or production owner invocation.
