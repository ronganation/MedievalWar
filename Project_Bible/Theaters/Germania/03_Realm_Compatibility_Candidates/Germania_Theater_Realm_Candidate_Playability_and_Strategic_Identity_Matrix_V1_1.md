## 1. Matrix Purpose

This matrix compares the principal Germania power families that could become playable Realms, associated polities, local entities, political-order participants, external interfaces, or Historical Emergence candidates. It recommends a coherent initial playable portfolio and a first development sequence without creating Realm folders, canonical IDs, Opening State records, character authorities, unit rosters, technology portfolios, payloads, or implementation work.

The matrix protects two goals at the same time:

1. Germania must feel politically rich enough to justify the Holy Roman setting.
2. Germania must not fragment into a full faction package for every county, bishopric, abbey, march, city, palace, and lordship.

```text
Candidate != Admitted Realm
Recommended != Canonical
Playable != Uniform Territory
Realm != Title
Realm != Political Order
Political Order Participant != Vassal By Default
Associated Polity != Decorative Minor
Local Entity != Empty Map Object
Nonplayable != Nonexistent
Ducal Title != Complete Realm
Regional Name != One Government
Later Importance != Opening Playability
Distinct Roster Idea != Distinct Realm
Map Space != Faction Requirement
```

## 3. Evaluation Method

### 3.1 Scoring dimensions

```yaml
EvaluationDimensions:
  HistoricalOpeningIdentity:
    asks: DoesTheCandidateExistAsARecognizable1062PoliticalActorOrOwnerNetwork

  IndependentStrategicAgency:
    asks: CanTheCandidateMakeMeaningfulDecisionsBeyondFollowingTheKingOrARegionLabel

  PlayerPromise:
    asks: DoesTheCandidateOfferAStableDistinctCampaignQuestion

  CharacterAndDynastyDepth:
    asks: CanTheCandidateSupportMeaningfulCharactersHouseholdsDynastiesOfficesAndSuccession

  GovernmentAndInstitutionDepth:
    asks: CanTheCandidateSupportDistinctGovernmentLawInstitutionAndPoliticalOrderInterfaces

  MilitaryAndRecruitmentDistinctness:
    asks: CanDistinctSourceObligationCommandSupplyAndBattleSystemsBeResearched

  EconomyPropertyPopulationAndInfrastructureDepth:
    asks: IsThereAResearchPathForMaterialAndSettlementSystems

  DiplomacyAndCrossTheaterValue:
    asks: DoesTheCandidateCreateUsefulExternalAndPoliticalOrderInterfaces

  HistoricalEmergenceDepth:
    asks: DoesTheCandidateSupportAlternativeDevelopmentWithoutForcingLaterHistory

  EvidenceReadiness:
    asks: IsThereEnoughSourceInfrastructureToBeginARealmPackageResponsibly

  AntiDuplicationValue:
    asks: DoesTheCandidateAddCapabilityRatherThanSplitAnotherCandidateForMapSymmetry

  LocalEntityCompatibility:
    asks: CanTheCandidateCoexistWithMeaningfulNonplayableActorsWithoutAbsorbingThem
```

### 3.2 Rating vocabulary

```yaml
Ratings:
  VeryHigh: DefiningStrengthOrEvidencePath
  High: StrongAndLikelySufficient
  Medium: UsefulButRequiresFocusedDevelopment
  Low: WeakOrDuplicativeAtCurrentScope
  Unknown: EvidenceNotYetRecovered
  NotApplicable: DimensionDoesNotApply
```

### 3.3 Dispositions

```yaml
Dispositions:
  AnchorPlayableCandidate: TheaterDefiningRealmCandidateRecommendedFirst
```
