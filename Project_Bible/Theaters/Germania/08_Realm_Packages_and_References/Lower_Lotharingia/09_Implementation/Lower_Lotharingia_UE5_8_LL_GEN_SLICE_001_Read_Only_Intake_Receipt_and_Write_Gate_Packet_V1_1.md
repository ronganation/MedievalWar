## 1. Purpose

The packet has four jobs:

1. preserve the exact definition-only scope of `LL_GEN_SLICE_001`;
2. capture live repository and source observations in one place;
3. force an explicit comparator, changed-file allowlist, validation set, and rollback baseline before any write;
4. produce a clear closed, conditionally ready, or blocked write-gate verdict.

The packet is not an implementation receipt, promotion record, registry proposal, payload, importer specification, Opening State record, or authorization to mutate the Unreal project.

## 2. Intake execution order

The read-only session must proceed in this order:

1. Read the controlling repository guidance and applicable READMEs.
2. Record repository identity, branch, head, status, and pre-existing changes.
3. Inspect the current Lower Lotharingia package guide, currentness register, general Realm authority, and first-definition binding packet.
4. Identify one actually implemented comparator faction using the same project layer intended for Lower Lotharingia.
5. Trace the comparator from source or authority through definition, provider, registry, query, test, and generated artifacts where those layers actually exist.
6. Determine whether the project already contains Lower Lotharingia or Frederick identifiers, definitions, references, tests, assets, or placeholders.
7. Select exact source passages for the limited general identity slice.
8. Record the minimum changed-file proposal, expected generated artifacts, validation commands, and rollback baseline.
9. Evaluate all entrance gates.
10. Stop and return this completed receipt. Do not write code or assets.

If any step would require mutation, record the blocked observation and continue only with safe read-only work.

## 12. Acceptance cases

1. **LL_INTAKE_001, repository truth:** all repository claims come from observed paths, status, or guidance.
2. **LL_INTAKE_002, current-source truth:** the selected general authority is verified through the package currentness chain.
3. **LL_INTAKE_003, exact passage binding:** every prospective field has an exact source locator and interpretation limit.
4. **LL_INTAKE_004, comparator reality:** the comparator exists in the target project layer and is traced through relevant files.
5. **LL_INTAKE_005, no architecture invention:** the proposal reuses an observed pattern or explicitly blocks on a missing pattern.
6. **LL_INTAKE_006, one Realm identity:** Lower Lorraine does not become a duplicate Realm.
7. **LL_INTAKE_007, person restraint:** Frederick is referenced only through a verified existing target.
8. **LL_INTAKE_008, Theater restraint:** Germania association does not duplicate Theater-owned content.
9. **LL_INTAKE_009, state separation:** definition representation creates no active campaign state.
10. **LL_INTAKE_010, collision safety:** existing names and identifiers are resolved before write authorization.
11. **LL_INTAKE_011, bounded allowlist:** every proposed changed file has a direct slice purpose.
12. **LL_INTAKE_012, generated-artifact disclosure:** generated or editor-touched outputs are known before mutation.
13. **LL_INTAKE_013, validation honesty:** selected tests are distinguished from executed results.
14. **LL_INTAKE_014, rollback safety:** rollback excludes pre-existing owner changes.
15. **LL_INTAKE_015, no hidden write:** intake creates no code, asset, cache, project, registry, or save mutation.
16. **LL_INTAKE_016, time-track integrity:** intake advances no historical, biological, or seasonal state.
17. **LL_INTAKE_017, clean stop:** the session returns the receipt without crossing the write gate.
18. **LL_INTAKE_018, blocked-path clarity:** unresolved issues identify the exact blocked field or file rather than rejecting the entire faction.
