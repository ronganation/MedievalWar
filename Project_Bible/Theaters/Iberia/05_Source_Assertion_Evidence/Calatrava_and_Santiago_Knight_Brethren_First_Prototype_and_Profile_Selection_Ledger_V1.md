# PART I. PURPOSE AND DECISION SEPARATION

## 1. Purpose

This ledger selects the first bounded Iberian military-order institutional package and the first knight-brethren master-profile sequence. It does not create Calatrava, Santiago, a unit profile, an opening instance, a stable identifier, a payload, or Unreal content.

## 2. Separate Decisions

```yaml
decisions:
  A_FirstInstitutionalPrototype:
    question: WhichOrderBestTestsTheSharedFrameworkInABoundedPackage
  B_FirstKnightBrethrenProfile:
    question: WhichFamilyCanReachMasterProfileWithoutDependingOnAnUnbuiltOrderPackage
  C_SequenceCoupling:
    question: ShouldTheFirstProfileBelongToTheFirstInstitutionalPrototype
```

The answers may differ in principle. For this sequence they align because the first profile depends on order-specific membership, houses, assignments, recovery, and ownership that should be established by its institutional package.

# PART V. SEQUENCE-COUPLING DECISION

## 13. Must Prototype and First Profile Match?

```yaml
universal_rule: false
current_sequence_decision: true
reason:
  - UnitProfileDependsOnOrderMembershipAndOwnership
  - RecruitmentDependsOnOrderHouseFortressAndSupport
  - AssignmentDependsOnGarrisonMissionAndJointCommand
  - RecoveryDependsOnInstitutionalCapacity
  - SameOrderSequenceProducesCleanerValidationAndRollback
```

Future order or unit work need not always follow this coupling. Here the coupling prevents a Santiago unit card from being designed ahead of the Santiago institution while Calatrava carries the actual prototype burden.
