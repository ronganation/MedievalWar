## 1. Plain-Language Purpose

This is a narrow implementation-support file. It answers one question only:

```text
If a file or folder is not included normally in the snapshot fingerprint,
what exactly is it, why is it being treated differently, who approved that
treatment, and what evidence is affected?
```

The final ledger prevents hidden, temporary, duplicate, inaccessible, conflict, or unusual entries from being silently ignored. Most snapshots should have no approved exclusions. An empty final ledger is valid when the complete package snapshot contains no justified exceptions.

```yaml
default_rule: IncludeEveryPhysicalEntry
silent_exclusion: prohibited
default_disposition: Hold
empty_final_ledger_permitted: true
empty_final_ledger_requires_complete_inventory_proof: true
```


Exclusion from the aggregate fingerprint does not authorize deletion from the package.

## 4. Permitted Exception Classes

```yaml
exception_classes:
  RetrievalArtifact:
    meaning: File created solely by an approved export or retrieval mechanism
  SynchronizationMetadata:
    meaning: Non-content metadata generated by the synchronization system
  TemporaryLockFile:
    meaning: Verified transient lock file with no substantive project content
  DuplicateExportWrapper:
    meaning: Proven wrapper or container duplicating separately inventoried content
  InaccessibleEntry:
    meaning: Entry recorded but unreadable, which normally blocks completeness
  PathNormalizationException:
    meaning: Physical path requires explicit canonicalization handling
  TimestampNormalizationException:
    meaning: Content identity is stable but timestamp behavior requires documented treatment
  PermissionMetadataException:
    meaning: Permission data cannot be preserved by the approved snapshot method
  OtherOwnerApprovedException:
    meaning: Exceptional case requiring explicit evidence and owner approval
```

Historical, old, draft, superseded, inconvenient, duplicate, or apparently irrelevant content is not excluded merely because of that status.

## 7. Approval Threshold

```yaml
approval_requirements:
  - exact physical entry is present in the before inventory
  - file SHA256 is recorded when applicable
  - exception class is valid
  - normal inclusion problem is explained
  - aggregate fingerprint impact is explicit
  - evidence population impact is explicit
  - downstream prohibited uses are explicit
  - owner authority is verified
  - owner decision references exact snapshot and entry identity
  - no completeness or content-integrity gap is hidden
  - deterministic serialization remains reproducible
```
