## Work Rules

### 1. Prefer substance over status churn

Do not create a successor merely because a strong file says `Draft`. A new version must add meaningful content, resolve a real contradiction, incorporate a controlling dependency, satisfy a real owner gate, or provide a bounded implementation handoff improvement.

### 2. Check for an existing equivalent first

Before creating a file:

- inspect the relevant numbered folder;
- search the exact filename, stable document ID, authority ID, and scope synonyms;
- check the current authority and its static-check companion;
- check whether the planned successor already exists under an equivalent filename;
- compare the immediate substantive source;
- compare against strong developed-faction benchmarks without homogenizing Barcelona;
- record supersession, parallel-scope, or duplicate disposition;
- create a new artifact only when the current package has a real gap.

### 3. Preserve the copy-first additive standard

Every authority successor must verify and preserve the complete immediate substantive source first. Preserve useful sections, tables, records, portfolios, named participants, directed relationships, uncertainties, implementation notes, owner boundaries, validations, migration dispositions, and evidence boundaries unless a removal is demonstrably justified.

```yaml
permitted_removal_reasons:
  - Outdated
  - Incorrect
  - Superseded
  - GenuinelyRepetitive
  - ConstitutionallyIncompatible

removal_ledger_required: true
compression_for_convenience: prohibited
ownership_separation_as_content_removal_reason: prohibited
```

### 4. Preserve the opening boundary

```yaml
scenario_opening: 1062-01-01
opening_campaign_season: Winter
Historical:
  progression_per_strategic_turn: 21 months
Biological:
  progression_per_strategic_turn: 7 months
Campaign_Season:
  progression_per_strategic_turn: 1 ordered step
  order: [Winter, Spring, Summer, Autumn]
```

The three tracks remain separate. No Realm file may redefine shared cadence, silently restore a universal seven-month turn, or derive Campaign Season solely from another track.

### 5. Preserve unresolved states honestly

`Unknown`, `IntentionalEmpty`, `ReviewOnly`, `Quarantined`, `HistoricalOnly`, `DefinitionOnly`, and `ExternalLock` remain distinct. None may be silently converted into `Active`, zero, false, absent history, consent, control, or a gameplay outcome.

### 6. Preserve ownership boundaries

An authority may discuss another owner’s subject as an interface without taking ownership. Barcelona may publish outgoing references and consume accepted external state, but it may not author another Realm’s, institution’s, shared Registry’s, or technical subsystem’s private state.

### 7. Do not overclaim validation

Document completion is not Unreal implementation. Static checking is not compilation or runtime validation. Proposed data assets, structures, tags, importer contracts, headers, and owner interfaces remain proposals until verified in the active Unreal project under the authorized implementation batch.
