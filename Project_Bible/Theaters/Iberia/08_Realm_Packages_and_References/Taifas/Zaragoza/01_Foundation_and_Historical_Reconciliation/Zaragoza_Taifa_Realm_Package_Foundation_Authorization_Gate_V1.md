## 1. Purpose

This Batch 6 gate decides whether Zaragoza may advance from Theater-owned evidence screening into a bounded compact foundation-documentation phase.

The gate authorizes only the minimum foundation authorities needed to reconcile sources, identity, ownership, and historical scope. It does not authorize physical folder creation, active Registry publication, Opening State creation, active characters, titles, sites, agreements, institutions, populations, forces, recruitment pools, economic values, payloads, or Unreal implementation.

## 6. Foundation Document Requirements

### 6.1 README and current authority index

Must include:

- current internal version and date;
- scenario opening and three-track time model;
- package status and complete nonmutation boundary;
- current evidence authorities;
- authorized and unauthorized downstream files;
- exact current next action;
- stop rules against status-file proliferation;
- placement status as Theater-owned until physical promotion.

It must not imply that a physical Zaragoza package already exists.

### 6.2 Verified source inventory

Must include:

- every current internal authority used;
- every external source actually opened or only located;
- source class, scope, access status, and permitted use;
- claim-to-source mappings;
- contradictions and unresolved questions;
- current OneDrive discovery results;
- the ReviewOnly Upper March garrison concept disposition;
- complete file manifest for the foundation set;
- no unsupported primary-source claims.

### 6.3 Historical reconciliation

Must reconcile, without fabricating:

- Zaragoza's independent opening-polity status;
- Ahmad al-Muqtadir and Banu Hud identity;
- title and transliteration uncertainty;
- succession uncertainty and later partition boundaries;
- Zaragoza and Lleida separation;
- site-by-site political geography;
- paria, protection, conflict, and external-relationship candidates;
- government, institutional, community, economy, population, culture, and Aljaferia boundaries;
- frontier and military capability versus active instances;
- exact distinctions from Seville, Badajoz, and Valencia.

### 6.4 Identity, Registry, and External Lock preflight

Must propose, not publish:

- stable identity candidates and aliases;
- Realm, faction, dynasty, title, person, site, institution, and relationship ownership classes;
- collision and duplicate checks;
- External Locks for neighboring Realms and uncertain actors;
- migration or quarantine treatment for stale aliases;
- prohibition against neighboring packages emitting Zaragoza private state;
- no active Registry rows.

```yaml
    action: DowngradeToDeployablePolityOrDefer

    action: NotAuthorizedNoMutationExpected
```

Rollback never deletes useful historical evidence or strips the original preflight record.

## 13. Stop Conditions

Stop the affected foundation document if:

- a current Zaragoza package or stronger source is discovered and not opened;
- a claim cannot be traced to a classified source;
- snippets or abstracts are presented as full source review;
- later borders, people, offices, forces, or palace fabric are backdated;
- Lleida is absorbed without exact dated authority;
- a candidate ID is treated as published;
- an External Lock is treated as ownership;
- an active person, title, site, agreement, institution, population, building, force, pool, or resource is created;
- a physical Realm folder is created before Package Integration approval;
- the compact package expands through status-only or repetitive documentation;
- work crosses into Opening State, payload, importer, Unreal, or runtime mutation.

Continue unaffected source reconciliation and documentation.
