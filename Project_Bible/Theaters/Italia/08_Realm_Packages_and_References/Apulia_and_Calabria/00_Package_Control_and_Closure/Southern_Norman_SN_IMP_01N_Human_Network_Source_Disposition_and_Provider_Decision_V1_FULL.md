## 1. Decision

**STOP before Human Network provider C++ and Venice V13.**

At the live V12 baseline, no accepted `HUM-00` or equivalent Human Network consumed-source manifest, and no Human Network-specific source-owner acceptance, exists in the Southern Norman package. Therefore there is no authorized source boundary to bind to a provider. The three SN-IMP-01N documents record the preparation, unresolved owners, and fail-closed decision; they are not an acceptance manifest and do not admit any source for implementation.

Do not:

- implement a Southern Norman Human Network provider or tests;
- add Human Network to shared presentation or shared review;
- create or pin Venice V13;
- create `HUM-00` by copying the sources or acceptance status from `CAM-00`, `CIV-00`, or `INT-00`;
- add Character, Person, relationship, title, office, household, command, Registry, Opening State, runtime, save, migration, or payload data;
- infer owner acceptance from a file being present, indexed, hashed, current in package navigation, or accepted for a different lane.

## 3. Required Gate to Resume

Resume only after all of the following are satisfied and explicitly evidenced:

1. **Human Network source authorization:** the responsible project/source owner supplies an accepted, Human Network-specific consumed-source manifest and owner-acceptance record. It must state its scope, lane set, exact source rows and roles, physical hashes, currentness, locators, source-owner routes, external-owner dependencies, and invalidation rules.
2. **Character portfolio reconciliation:** the Character/Person and Historical owners disposition the five opening candidates (including the preflight versus Character Authority class split), all seven review-only subjects, Mauger’s predecessor-only status, and the external references. They must preserve uncertainty and decide no unsupported claim.
3. **Currentness and identity conflicts:** the owners disposition Alberada V1/V1.1, Matilda/Maud, Geoffrey identity/life chronology, Judith/Roger marriage timing, William’s life/title chronology, and child birth/life evidence before those claims become source rows.
4. **Cross-domain owner routing:** Character, Dynasty, Household/Court, Political/Governance, Ecclesiastical, Military/Command, Diplomacy, Registry, Opening State, and external owners accept only their own fact and state boundaries. No route identifier may be invented.
5. **Fresh re-entry evidence:** after the source gate is accepted, repeat live path/hash/currentness and baseline captures; invalidate a row if its path, version, bytes, hash, status, locator, scope, or owner disposition changes.
6. **Separate implementation authorization:** a later task must explicitly authorize the provider core after the accepted source boundary. Presentation integration and Venice V13 require their own gates and must not be inferred from a provider-only authorization.

An accepted source manifest would make a later provider review eligible; it would not itself authorize canonical identities, relationships, opening records, shared presentation, runtime, or V13.
