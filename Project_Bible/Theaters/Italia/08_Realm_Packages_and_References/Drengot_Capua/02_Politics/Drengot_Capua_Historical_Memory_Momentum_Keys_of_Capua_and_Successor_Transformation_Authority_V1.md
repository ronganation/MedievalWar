## 1. Purpose

This authority defines how Drengot Capua remembers its past, how remembered and recorded events shape later political behavior, how historically grounded momentum becomes more or less likely without becoming a script, how The Keys of Capua resolves from world state, and how the Realm may survive, narrow, divide, or transform after Richard I.

It does not recreate the Realm foundation, political constitution, character authority, or AI strategy. It consumes those authorities and governs the historical pressures that accumulate through them.

```yaml
AuthorityPurpose:
  - DefineMemoryWithProvenanceAndAudience
  - DefineHistoricalMomentumWithoutDateDeterminism
  - MatureKeysOfCapuaIntoAFullStaticEmergenceContract
  - ConnectConductToLaterRecognitionParticipationAndSuccession
  - PermitNonoccurrenceReversalRecoveryAndTransformation
  - PreserveAlternativeHistoryWithinEvidenceAndWorldState
  - PreventHistoricalEventsFromCreatingUnsupportedResources
```

## 2. Strong Historical-System Verdict

Drengot Capua should not proceed through a predetermined historical checklist. Its history should be generated through remembered acts, surviving institutions, documented claims, living participants, victories, defeats, settlements, broken promises, dynastic transitions, Papal relations, and external intervention.

The historical path should feel recognizable because real historical pressures are present. It should remain playable because those pressures can resolve differently when the world state differs.

```yaml
HistoricalSystemVerdict:
  model: ProvenanceBasedMemoryAndConditionalMomentum
  primary_opening_emergence: KeysOfCapua
  opening_historical_pressure: ActiveAtDesignLevel
  fixed_date_resolution: false
  guaranteed_historical_outcome: false
  nonoccurrence_valid: true
  reversal_valid: true
  alternate_successor_forms_valid: true
  unsupported_later_history_back_projection: false
```

```text
Historical Pressure != Historical Script
Memory != Objective Truth
Recorded Claim != Universal Acceptance
Date Window != Guaranteed Event
Emergence != Free Reward
Successor Transformation != Automatic Faction Replacement
```

## 4. Historical Memory Model

Historical memory is an actor- and institution-specific record of experienced, reported, documented, commemorated, or inherited events. It is not one global truth value.

```yaml
MemoryRecordDimensions:
  memory_id: StableReference
  subject: PersonRealmInstitutionPlaceTitleClaimOrEvent
  holder: PersonGroupInstitutionSettlementOrRealmInterface
  source_type:
    - Witnessed
    - Reported
    - Documented
    - Commemorated
    - Inherited
    - Rumored
    - Contested
  confidence: HolderSpecific
  date_or_window: ExplicitWhenKnown
  provenance: Required
  interpretation: HolderSpecific
  emotional_inference: Prohibited
  political_relevance: Conditional
  decay_or_reinforcement: WorldStateDriven
```

## 5. Memory Is Directional and Unequal

```text
RichardRemembersCapuanResistance != CapuanActorsRememberRichard
PapalRecognitionRecord != LocalRecognitionMemory
AversanDynasticMemory != CapuanPoliticalMemory
NormanVictoryMemory != LombardSubmissionMemory
DocumentedGrant != UndisputedPropertyMemory
```

The same event may create different memories for different holders. Reverse-direction memories are never inferred.

## 9. Historical Momentum Model

Historical Momentum is the changing probability and availability of developments whose historical pressure exists in the world state. It cannot force an outcome when supporting conditions fail.

```yaml
MomentumDimensions:
  Relevance:
    question: IsTheDevelopmentStillConnectedToCurrentConditions
  Pressure:
    question: AreActorsInstitutionsAndClaimsDrivingIt
  Capacity:
    question: CanTheRequiredPeopleMaterialAndAuthorityAct
  Recognition:
    question: WillRelevantAudiencesAcceptOrContestIt
  Opportunity:
    question: IsThereAUsableWindow
  Resistance:
    question: WhatOppositionCanBlockReverseOrTransformIt
  Memory:
    question: DoPastEventsReinforceOrUndermineIt
```
