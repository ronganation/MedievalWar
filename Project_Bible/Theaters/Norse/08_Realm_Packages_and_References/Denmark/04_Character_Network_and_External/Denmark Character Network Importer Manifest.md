### 1. Concise Verdict

Implement this manifest as Denmark's bounded, deterministic Character Network handoff for 1 January 1062.

The approved opening package contains:

- **20 directed entries**;
- **12 Denmark-owned directions**;
- **8 conditional or externally owned directions**;
- **4 immediately eligible active directions**;
- **2 basis-only sibling directions**;
- **6 Denmark-owned conditional directions**;
- **4 conditional external directions**;
- **4 external-owner reverse directions**;
- **zero automatic reverse edges**;
- **zero runtime mutations during static or dry preflight**.

The network is sparse, directed, asymmetric, uncertainty-preserving, child-safe, office-safe, migration-safe, and compatible with a shared Character Network owner. Denmark supplies scenario content and activation requirements. Denmark does not create a realm-specific relationship runtime, mutate external owner records, or convert unknown values into invented precision.

Core rule:

**Kinship, marriage, office, title, shared religion, conflict, or proximity may establish context. None automatically creates trust, loyalty, knowledge, authority, or reciprocal relationship state.**

### 4. Opening Network Thesis

Denmark's opening political network is deliberately narrow. It focuses on relationships that materially affect:

- royal-family continuity;
- succession uncertainty;
- protected minors;
- communication across households and realms;
- crown-church cooperation;
- Hamburg-Bremen ecclesiastical influence;
- Denmark-Norway conflict pressure;
- Obotrite marriage and external access.

The package is not an exhaustive directory of Danish elites. Regional magnates, additional clergy, household actors, military commanders, and local patrons should enter only when canonical identity, evidence, ownership, and strategic consequence justify inclusion.

The network's campaign function is to make Denmark's choices legible without turning politics into one opinion score.

### 6. Approved Status Vocabulary

### 21. Opening-State Handoff

The network manifest may be submitted once during new-campaign initialization after:

1. registries and package versions load;
2. persons and lifecycle states resolve;
3. activation tiers resolve;
4. households and locations resolve where available;
5. titles and offices resolve;
6. underage roles validate;
7. claims and conflict context initialize;
8. external locks resolve where possible.

Then:

9. the ordered network batch is submitted;
10. the Character Network owner validates and creates permitted state;
11. blocked records remain conditional or externally owned;
12. traces and state hashes are recorded.

If the campaign has already initialized, Opening State seeds are not resubmitted. Only an explicit versioned migration may run.

### 26. Validation Contract

#### 26.1 Fatal

- counts differ from 20/12/8 or 4/2/6/4/4;
- duplicate directed identity;
- source equals target;
- required person unresolved;
- owner mismatch;
- external reverse direction authored as Denmark-owned;
- reverse edge auto-generated;
- unsupported dimension or qualitative band;
- Unknown converted to zero;
- missing confidence, visibility, or activation metadata;
- sibling rivalry initialized as fact;
- Eric receives adult political dimensions;
- William record activates without Roskilde office occupancy;
- Sigrid record activates without required location or household state;
- external lock creates a local person;
- Adalbert resolves as two people;
- Harald Hardrada resolves to a non-Norway duplicate;
- later battle, peace, death, reign, marriage, or sainthood initializes relationship state;
- review or quarantine identity activates;
- deprecated ID enters new content or save;
- alias chain exists;
- importer bypasses the Character Network owner;
- Opening State overwrites an advanced save;
- deterministic ordering is absent.

#### 26.2 Review-safe

- canonical `person.*` to `Character.*` normalization pending;
- external person identity resolved but reverse owner content absent;
- household or location evidence incomplete;
- qualitative mapping asset unavailable;
- evidence references incomplete;
- regional network expansion deferred.

Review-safe records remain blocked from irreversible activation when the unresolved field is required.

#### 26.3 Warning

- all kin records use identical values;
- private dimensions appear globally visible;
- communication access ignores geography or household;
- qualitative bands map to numbers without a versioned mapping table;
- relationship change has no strategic consequence route;
- player-facing trace is too verbose;
- the network remains royal-only after supported regional actors become available.
