# PART I: VERDICT, PURPOSE, AND OWNERSHIP

## 1. Concise Verdict

Sweden has enough developed authority coverage to inventory a future January 1062 Opening State, but this plan does not create that Opening State. The current safe result is a candidate assembly and owner-binding plan with unresolved active-state, holder, participant, location, property, route, institution, military, economy, knowledge, Theater-association, importer, persistence, and validation dependencies.

The plan may identify approved definitions such as Stenkil, the Swedish Realm, royal faction, Crown, royal title, kingly office, House Stenkil, Royal Household, regional surfaces, political-center candidates, church definitions, route families, settlement candidates, and other bounded subjects. Identification does not execute a binding.

No active binding may be inferred from a definition, filename, folder location, cross-reference, historical conclusion, or candidate record. Opening State assembly must occur only after authoritative owners approve exact opening records and the appropriate implementation, importer, save, migration, replay, and validation gates are satisfied.

## 2. Purpose

This plan defines:

- the non-mutating Opening State assembly boundary;
- owner-binding record requirements;
- candidate subject-family inventory;
- required owners, gates, and blockers;
- apply-once, advanced-save, importer, persistence, and determinism boundaries;
- rejection and abstention rules;
- handoff requirements for a later Opening State authority, owner-routing manifest, and importer payload.

## 3. This Plan Owns

- Sweden-specific Opening State assembly planning;
- candidate binding categories;
- dependency and blocker inventory requirements;
- plan-level status, gate, and rejection classifications;
- owner-routing and handoff requirements;
- static validation of this plan's internal consistency.

## 4. This Plan Does Not Own

- canonical ID creation or Registry mutation;
- active state, Opening State, owner bindings, holders, participants, locations, property, institutions, routes, forces, economy, supply, knowledge, AI, presentation, or Theater association;
- importer schema, payload fields, component paths, save keys, migration rules, runtime commands, or implementation;
- validation evidence outside this static plan;
- direct mutation of authoritative game state.

## 5. Shared Owner Rule

Every subject remains controlled by its shared authoritative owner. This plan routes candidate bindings to those owners and records blockers. It does not replace, duplicate, broaden, or override any owner.
