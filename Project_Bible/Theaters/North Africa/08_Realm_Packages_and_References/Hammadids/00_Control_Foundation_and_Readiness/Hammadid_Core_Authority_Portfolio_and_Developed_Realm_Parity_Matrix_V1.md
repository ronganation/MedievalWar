## 1. Purpose

This matrix rebuilds the Hammadid development sequence around the mature Realm core used elsewhere in the project. It distinguishes true core authorities from specialist authorities, maps current Hammadid files to developed-Realm capability requirements, records confirmed gaps, and authorizes the next core file without fabricating Opening State facts.

The Hammadid package is not being restarted. Existing specialist work remains valuable. The correction is sequencing and control: core authorities must become explicit, navigable, mutually consistent, and opening-ready before the specialist portfolio can be treated as a mature Realm package.

## 2. Core-Before-Specialist Rule

```text
source inventory before historical reconciliation
historical reconciliation before personality interpretation
personality before AI weighting
people before relationships
characters before dynastic and household state
dynastic and household state before opening bindings
definitions before Opening State
candidate references before canonical Registry allocation
Opening State plan before populated Opening State
evidence and owner gates before implementation handoff
specialist breadth does not replace the Realm core
```
